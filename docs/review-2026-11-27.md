# SVG Master 全面审查与修复（2026-11-27）

范围：整体逻辑、提示词、使用流程、UI 布局，以及用户确认的两个预期行为：

1. 点击「清空全部」后提示词回到默认提示词；
2. 新建项目默认使用 SVG 快速模式。

这两条已按预期实现，并顺带修掉审查中发现的若干相关缺陷。文末列出尚未改动、建议后续处理的优化项。

## 一、已按预期实现

| # | 预期行为 | 原实现的问题 | 当前实现 |
|---|---|---|---|
| 1 | 清空全部后提示词回到默认提示词 | 清空统一 `setPrompt('')`；启动 / 保存供应商时又可能从别处注入默认值，行为不稳定 | 清空时显式设置 `S.defaultPrompt`（像素工作区保持为空）；启动或恢复草稿时若 SVG 提示词为空也回落到默认值 |
| 2 | 清空 / 重启后提示词可恢复 | 提示词只在内存；内置窗口随机端口导致 `localStorage` 的 origin 每次启动都可能变化，不能可靠保存草稿 | 提示词按工作区写入 `settings.json` 的 `draftPrompt` / `pixelDraftPrompt`（输入防抖 PUT，`pagehide` 用 `sendBeacon` 兜底）；清空写入默认值 |
| 3 | 新建 SVG 项目默认快速模式 | `projectAction` 只在 `projectId` 变化时重置模式，而 SVG 快照没有 `projectId`；新建也没有明确默认值，直接继承上次模式 | 新建 SVG 工程固定为 `quick`；打开工程沿用当前模式；快速工程手动加到多图层后，生成前会被拦下并提示切换 |
| 4 | 切换 SVG 工程时右侧输出与 session 不残留 | SVG 工程的 `projectId` 恒为空，`oldProject?.projectId !== new?.projectId` 永远不成立 | 用 `projectId` → `dir` → `name` 兜底判断工程是否真的换了；`saveas` 显式排除，保持「另存为不解除生成锁」的原有约定 |
| 5 | 快速模式生成结果必须落进工程 | 快速模式没有图层工具，`emit_svg` 只把 SVG 发给前端并写入 `out/`，活动图层始终为空，重开 / 另存为会丢图 | 后端在 `EvSVG` 且图层工具关闭时把交付内容写回活动图层；写入失败会发一条 warn 日志。新增 `TestQuickModePersistsDeliveredSVGIntoProject` 覆盖 |
| 6 | GIF 开关开启时不能无主题生成 | `startRun` 只判断整个 textarea 是否为空；GIF 后缀本身非空 | 判断「用户是否真的写了主题」改为只看后缀之前的部分；同时后端在非像素模式下拒绝空提示词（400），不再回落到 pelican 演示主题 |
| 7 | 启动后工作区与创作模式一致 | `workspace` 与 `genMode` 分开持久化，切换模式时只写了 `genMode` | 启动时以 `genMode` 校正工作区；切换模式与保存设置时同步写入 `workspace` |
| 8 | 提示词库卡片的比例建议要生效 | 只替换了模板文本 | 按 `ratio` 精确匹配预设名 → `W×H` → `16:9` 顺序匹配并切换画布 |
| 9 | 窄窗口顶栏不溢出 | 顶栏固定 48px、不换行；侧栏固定宽度 | ≤1240px 收起品牌文字；≤1060px 允许顶栏换行、操作区自动换行 |

> 补充：内置窗口默认绑定随机端口（`api.New(store, 0)`），`localStorage` 的 origin 会随之变化。因此提示词草稿不能只放在 localStorage，已改为跟着 `data/settings.json` 走；这也顺带解释了为什么主题 / 右栏折叠状态在小概率下会「重启后复位」（它们仍用 localStorage，见后文建议）。

## 三、审查结论

### 1. 提示词

- 三套系统提示词与工具集的对应关系是正确的：
  - 快速模式：`OutputSpec`，不下发图层工具；
  - 多图层模式：`OutputSpecLayers` + `multiStepNote` + `layerToolsNote`，`emit_svg` 只覆盖当前图层；
  - 像素模式：`pixelSystemPrompt` / `pixelAnimSystemPrompt`，叠加 GIF 静态/动图附加提示。
- 提示词库 `internal/svg/prompts.json`：41 条、8 个分类、无重复 id、除 pelican 外全部包含 `{{subject}}`，无编码损坏。
- 用户提示词与输出规范解耦，方向正确；默认提示词现在只承担首次运行的演示作用。
- 建议（未改）：
  - `extractSubject` 只认识 `generate an svg of ...` / `svg of ...`。当前输入已经是英文模板时，再点另一张卡片通常提取不到主题，会把主题留空；可以记住上一次成功提取的主题作为兜底。
  - 模板全部是英文，中文用户需要自行替换主题；可考虑增加少量中文模板或双语说明。
  - GIF 后缀目前直接显示在 textarea 里。更清晰的做法是把它做成输入框下方的只读标记，而不是可看见的长段固定文本。

### 2. 整体逻辑

- 工程 / 会话已经统一为「历史跟着工程走」，方向正确；像素与 SVG 的工作区切换、生成锁、清空顺序也都有明确边界。
- 已修复的风险：
  - SVG 工程之间切换不重置 session / 右侧输出；
  - 快速模式交付不落图层，导致重开或另存为丢图；
  - 快速模式多图层时交付与图层合成冲突（生成前拦截）。
- 仍建议关注：
  - **工程弹窗没有「另存为工程」入口**：快速模式下只有关窗询问时才能另存为正式工程，编辑中途想保存只能关窗。`/api/project/saveas` 已经存在，建议在工程弹窗增加一个方框。
  - **启动每次都强制选工程**：`bootProject()` 无条件弹窗，`/api/project` 返回的 `recent` / `last` 没有在 UI 中使用；`.recent-list` 样式也还在。建议增加「继续上次工程 / 最近工程」列表。
  - **`projectAction` 重复应用工程**：先 `applyProject(r.project)`，随后 `loadProjectMeta()` 再 `applyProject` 一次；可以合并成一次，减少多余的渲染与像素模块同步。
  - **快速模式仍显示图层面板与「＋」**：快速模式交付单层，允许手动加层会在生成时被拦截。更一致的做法是在快速模式下禁用「新建图层 / 复制 / 删除」等图层操作，或给出明确提示。
  - **SVG 快照没有稳定的 projectId**：前端只能用目录兜底。若以后需要更可靠的工程身份，可让后端为 SVG 工程暴露稳定 id 或 `dir` 哈希。
  - **打开项目时的模式**：现在打开工程沿用当前创作模式。若希望「打开工程永远按工程自身的历史工作方式」，需要把创作模式也存进 `project.json`。
  - **模型菜单里的死分支**：`openModelMenu` 中「切组后默认选第一个模型」后面的 `if (!first && S.settings.activeModel ...)` 永远不成立，可删除。
  - **未使用的状态 / 引用**：`S.mode`、`S.paused`、`S.lastStats`、`pixelAnimBar`（DOM 不存在）等；`.proj-tabs`、`.mode-seg`、`.hint-line`、`.seg`、`.big-raw` 等样式已无对应结构。

### 3. 使用体验

- 「清空全部」的确认文案、执行顺序（先停任务再清空）与最终状态一致；清空后提示词恢复为默认演示主题。
- 提示词现在按工作区记忆，切换 SVG / 像素不再互相覆盖，重启也能恢复。
- 新建 SVG 工程默认快速模式，需要分层时再手动切到多图层。
- 建议（未改）：
  - **主题 / 右栏折叠状态仍用 localStorage**：内置窗口端口随机，重启后可能复位。若要像提示词一样稳定，建议一并迁到 `settings.json`（或固定一个本地端口，但要评估端口占用与安全边界）。
  - 工程弹窗的「新建项目」只填名字，随后才弹文件夹选择器；中途取消会停在原弹窗，属于可接受但可以更明确提示「已取消」。
  - 快速模式保存按钮目前导出单文件 SVG；正式「保存工程」只在退出时询问。与上文的「另存为工程」入口是同一个问题。
  - 顶部 `清空全部` 在 SVG/像素两种工作区共用，像素模式下会清空画板但保留工程位置，文案可以针对像素模式再具体一点。

### 4. UI 布局

- 主结构（左栏 320 / 中栏自适应 / 右栏 300）在默认 1560×900 窗口下合理；右栏各块独立折叠、模型输出占剩余高度，层级清楚。
- 画布工具栏、像素工具栏、时间轴在 1400 / 1000 宽度下均能换行；本次补了 ≤1060px 的顶栏换行与 ≤1240px 的品牌名收起。
- 仍建议：
  - 为窗口设置最小尺寸，或继续细化 <900px 的三栏布局（当前左右栏固定 290/270，窗口再小中栏会很窄）。
  - 顶栏按钮越来越多（模型、主题、清空、工程、复制、保存、导出…），后续可把低频项收进「更多」菜单。
  - 无障碍：主题按钮只有 `title`，建议补 `aria-label`；文件选择、拖拽区目前依赖视觉提示，键盘用户只能用隐藏 input，建议补可见的「选择文件」按钮。
  - 状态提示（toast）在底部居中，模型输出很长时容易被忽略；错误类 toast 可以延长停留或加可关闭按钮。

- `README.md` 的界面、三档模式、GIF 说明已按当前实现更新；`INTERFACES.md` 的三档枚举与切换规则、abort 字段也已同步。
